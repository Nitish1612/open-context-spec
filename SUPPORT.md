# Support

## Questions and discussion

For general questions, design discussion, or "how would I model X in OCS"
questions that aren't yet a specific bug report or a concrete spec change
proposal, use
[GitHub Discussions](https://github.com/Nitish1612/open-context-spec/discussions)
(once enabled — see `docs/github-setup.md` — until then, open an issue with
the `discussion` label instead).

## Bugs

Use the **Bug report** issue template. Include a minimal reproduction
(a small context document plus the command/code that triggers the issue)
wherever possible — see [CONTRIBUTING.md](./CONTRIBUTING.md).

## Feature requests

Use the **Feature request** issue template for SDK/CLI capabilities, or
the **Specification change proposal** template for changes to the schema,
vocabulary, or semantics — the two have different review bars, see
[CONTRIBUTING.md](./CONTRIBUTING.md#making-a-specification-change).

## Security

**Do not** open a public issue for a suspected vulnerability. See
[SECURITY.md](./SECURITY.md) for the private reporting process.

## This is a draft, not a support contract

Open Context Specification is an experimental community draft (see the
README). There is no SLA on response times; maintainers are volunteers.
That said, clear, minimal, reproducible reports get looked at fastest.
